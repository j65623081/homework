# Наивный прогон

Этап 3 цикла из задания: «один короткий промпт, без спеки и без правил».
Результат сохранён как есть и **не правится** — он нужен только для сравнения с итоговым
прогоном. Код в этой папке в сдаваемый сервис не входит.

- **Дата:** 2026-08-16
- **Сессия:** 1, шаг 4
- **Исполнитель:** субагент Claude Code (независимая сессия со своим контекстом)

## Промпт — дословно

Субагент получил ровно одну содержательную фразу:

> сделай API для заметок с тегами

Вокруг неё была только техническая обвязка изоляции — работать в отдельной папке вне
репозитория, не читать ничего за её пределами, ничего не уточнять, выбрать стек самому.
Ни спецификации, ни правил проекта, ни требований задания, ни упоминания PHP и Laravel
субагент не получал.

## Как проверялось, что изоляция сработала

Изоляция субагентом слабее, чем отдельное окно: теоретически правила проекта могли
просочиться в его контекст. Проверяется это по результату, и результат говорит, что
не просочились:

- выбран **Node.js**, хотя `AGENTS.md` фиксирует PHP 8.2 и Laravel;
- хранилище сделано **в памяти**, хотя и задание, и `AGENTS.md` требуют файл;
- эндпоинтов девять, хотя спека фиксирует пять.

Если бы субагент прочитал правила проекта, он не сделал бы ни одного из этих трёх выборов.

## Что получилось

**Стек, выбранный агентом самостоятельно:** Node.js 22 (ESM), встроенный `node:http`,
ноль внешних зависимостей, тесты на `node:test`, `id` через `node:crypto.randomUUID`.

**Файлы:** `package.json`, `src/server.js`, `src/app.js`, `src/store.js`,
`src/validation.js`, `src/errors.js`, `test/helpers.js`, `test/notes.test.js`,
`test/list.test.js`, `README-agent.md` (README, написанный самим агентом; переименован,
чтобы не путался с `README.md` проекта).

**Эндпоинты — девять:**

```
GET    /health
GET    /notes            ?tag= (повторяемый) &match=all|any &q= &sort= &limit= &offset=
POST   /notes
GET    /notes/:id
PUT    /notes/:id
PATCH  /notes/:id
DELETE /notes/:id
POST   /notes/:id/tags
DELETE /notes/:id/tags/:tag
GET    /tags
```

**Хранилище:** `Map<id, note>` в памяти плюс обратный индекс `Map<tag, Set<id>>`.
**Данные не переживают перезапуск процесса.**

## Проверено самостоятельно, а не со слов агента

Агент отчитался «40 тестов, 40 pass». По правилам проекта отчёт доказательством не является,
поэтому прогон повторён вручную.

Первая попытка провалилась — но провалился **вызов**, а не код:

```
$ node --test test/
# tests 1
# pass 0
# fail 1
    code: 'MODULE_NOT_FOUND'
```

Причина в том, что в `package.json` скрипт объявлен как `node --test` без аргумента,
а передача каталога сбивает поиск тестов. Правильный вызов:

```
$ npm test
# tests 40
# suites 7
# pass 40
# fail 0
# duration_ms 296.3053
```

Отчёт агента подтвердился полностью. Записываю это ровно так, как вышло: проверка
опровергла не агента, а меня — и если бы я остановился на первом выводе, в журнал ушёл бы
неверный вывод «наивный прогон не запускается».

Живой сервер тоже поднят и опрошен:

```
$ PORT=3517 node src/server.js
notes-api listening on http://127.0.0.1:3517

$ curl -X POST .../notes -d '{"title":"Test","tags":["  Shopping ","shopping","to  do",""]}'
{"id":"4d764646-...","title":"Test","content":"","tags":["shopping","to-do"],
 "createdAt":"2026-08-16T20:47:35.641Z","updatedAt":"2026-08-16T20:47:35.641Z"}

$ curl -X POST .../notes -d '{"tags":["a"]}'
{"error":{"code":"validation_failed","message":"Request body failed validation",
 "details":[{"field":"title","message":"is required"}]}}
HTTP 422
```

Видно вживую: `["  Shopping ","shopping","to  do",""]` превратилось в `["shopping","to-do"]` —
пустой тег исчез молча, а пробел внутри тега стал дефисом. Ни о том, ни о другом клиент
из ответа не узнаёт.

Ещё одно расхождение, которое всплыло только на живом ответе: имена полей —
**`createdAt` и `updatedAt` в camelCase**. Спецификация итогового прогона фиксирует
`snake_case` (`created_at`). Решение о стиле именования агент тоже принял за меня,
и заметно это стало не по коду, а по фактическому ответу сервера.

## Что агент решил за меня

Каждая строка — решение, которое в итоговом прогоне принимал человек на этапе спецификации.

| Что | Решение наивного прогона | Кто решал |
|---|---|---|
| Язык и фреймворк | Node.js 22, `node:http`, ноль зависимостей | Агент |
| Хранилище | **В памяти**, данные теряются при перезапуске | Агент |
| Число эндпоинтов | 9 | Агент |
| Отдельные эндпоинты для тегов | `POST /notes/:id/tags`, `DELETE /notes/:id/tags/:tag`, `GET /tags` | Агент |
| `PATCH` в дополнение к `PUT` | Есть, требует хотя бы одно поле | Агент |
| Фильтр по нескольким тегам | `?tag=` повторяемый, `match=all\|any`, по умолчанию AND | Агент |
| Сортировка | Параметр `?sort=`, набор полей выбран агентом | Агент |
| Пробелы внутри тега | Схлопываются в дефис: `"to  do"` → `to-do` | Агент |
| Пустой тег в массиве | **Молча выбрасывается** | Агент |
| Разрешённые символы в теге | Буквы любого алфавита, цифры, `-_.`; иначе 422 | Агент |
| Нормализация Unicode | NFC | Агент |
| Потолок числа тегов | 20 | Агент |
| Длина тега | ≤ 32 | Агент |
| Длина `title` | 1..200 | Агент |
| Имя и длина текстового поля | `content`, ≤ 10000 | Агент |
| Предел размера тела | 256 KB | Агент |
| Ответ на неизвестное поле | Отвергается | Агент |
| Разделение 400 и 422 | 400 — не разобрал, 422 — разобрал, но не годится | Агент |
| Коды сверх минимума | 405 с заголовком `Allow`, 413, 415 | Агент |
| Что делать при пустой выборке | 200 с пустым списком | Агент |
| Стиль имён полей в JSON | `camelCase` (`createdAt`) | Агент |
| Имя поля с датой создания | `createdAt`, а не `created_at` | Агент |

Отдельно стоит отметить: часть этих решений **совпала** с тем, что человек выбрал
на этапе спецификации, — отвергать неизвестные поля, отдавать 200 на пустую выборку,
разделять 400 и 422 именно так. Это не делает наивный прогон эквивалентным: совпадение
обнаруживается только тем, что решения записаны и их есть с чем сверить.

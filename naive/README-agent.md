# Notes API

HTTP API для заметок с тегами. Node.js (>= 18.17), ESM, **ноль внешних зависимостей** —
только встроенные модули (`node:http`, `node:crypto`, `node:test`).

## Запуск

```bash
node src/server.js          # http://127.0.0.1:3000
PORT=8080 node src/server.js
npm test                    # node --test, 40 тестов
```

Установка зависимостей не нужна: их нет.

## Эндпоинты

| Метод | Путь | Описание |
|---|---|---|
| GET | `/health` | статус сервиса, число заметок, uptime |
| GET | `/notes` | список с фильтрами и пагинацией |
| POST | `/notes` | создать заметку → `201` + заголовок `Location` |
| GET | `/notes/:id` | одна заметка |
| PUT | `/notes/:id` | полная замена (непереданные поля сбрасываются) |
| PATCH | `/notes/:id` | частичное обновление |
| DELETE | `/notes/:id` | удалить → `204` |
| POST | `/notes/:id/tags` | добавить теги к заметке (объединение) |
| DELETE | `/notes/:id/tags/:tag` | убрать один тег |
| GET | `/tags` | все теги со счётчиками использования |

### Параметры `GET /notes`

| Параметр | Значение | По умолчанию |
|---|---|---|
| `tag` | фильтр по тегу, можно повторять: `?tag=work&tag=home` | — |
| `match` | `all` (AND) или `any` (OR) для нескольких тегов | `all` |
| `q` | подстрока в заголовке или тексте, без учёта регистра | — |
| `sort` | `createdAt`, `updatedAt`, `title` c префиксом `-` для убывания | `-createdAt` |
| `limit` | 1..100 | 20 |
| `offset` | ≥ 0 | 0 |

Ответ: `{ "items": [...], "pagination": { "total", "limit", "offset", "count" } }`.

### Модель заметки

```json
{
  "id": "uuid-v4",
  "title": "Купить молоко",
  "content": "в магазине у дома",
  "tags": ["shopping", "to-do"],
  "createdAt": "2026-08-16T20:44:14.153Z",
  "updatedAt": "2026-08-16T20:44:14.153Z"
}
```

## Примеры

```bash
curl -X POST localhost:3000/notes -H 'Content-Type: application/json' \
  -d '{"title":"Купить молоко","content":"2%","tags":["Shopping","to  do"]}'

curl 'localhost:3000/notes?tag=shopping&match=any&limit=10'
curl 'localhost:3000/notes?q=молоко'
curl localhost:3000/tags
curl -X DELETE localhost:3000/notes/<id>/tags/shopping
```

## Хранилище

In-memory, класс `NoteStore` (`src/store.js`):

- `Map<id, note>` — доступ по id за O(1), порядок вставки сохраняется;
- `Map<tag, Set<id>>` — обратный индекс по тегам, выборка по тегу не требует полного перебора;
  при `match=all` пересечение начинается с самого маленького набора;
- наружу отдаются копии заметок, мутировать состояние снаружи нельзя;
- индекс поддерживается синхронно при create/update/delete, теги без заметок исчезают из `/tags`.

Данные живут в памяти процесса и пропадают при рестарте. Хранилище инкапсулировано
за узким интерфейсом (`create/get/update/delete/list/tags`), так что замена на SQLite
или Postgres — это один новый файл без правок в слое HTTP.

## Правила валидации

| Поле | Правило |
|---|---|
| `title` | обязателен, строка, обрезается по краям, 1..200 символов, пустой/пробельный → 422 |
| `content` | необязателен, строка, ≤ 10000 символов, `null`/отсутствие → `""` |
| `tags` | массив строк, ≤ 20 тегов, каждый ≤ 32 символов после нормализации |
| тело | только JSON, ≤ 256 KB, неизвестные поля отвергаются (защита от опечаток вроде `titel`) |

### Нормализация тегов

1. Unicode NFC — чтобы одинаковые на вид строки не давали два разных тега.
2. `trim` по краям.
3. Внутренние пробелы схлопываются и заменяются дефисом: `"to  do"` → `"to-do"`.
4. Нижний регистр: `Work`, `WORK`, `work` — один тег.
5. Пустые и пробельные значения **молча выбрасываются** — это не ошибка, а мусор от UI.
6. Дубликаты после нормализации схлопываются, порядок первого появления сохраняется.
7. Допустимые символы после нормализации: буквы (любой алфавит), цифры, `-`, `_`, `.`;
   первый символ — буква или цифра. Иначе 422.

Те же правила применяются к тегам в query-параметре `?tag=` и в пути
`DELETE /notes/:id/tags/:tag`, поэтому найти заметку по `?tag=%20WORK%20` можно.

## Ошибки

Единый формат:

```json
{ "error": { "code": "validation_failed", "message": "...", "details": [ { "field": "title", "message": "is required" } ] } }
```

| Код | Когда |
|---|---|
| 400 `bad_request` / `invalid_query` | битый JSON, пустое тело, неверные query-параметры |
| 404 `not_found` | нет такой заметки, тега у заметки или маршрута |
| 405 `method_not_allowed` | путь есть, метод нет; отдаётся заголовок `Allow` |
| 413 `payload_too_large` | тело больше 256 KB |
| 415 `unsupported_media_type` | `Content-Type` не `application/json` |
| 422 `validation_failed` | тело — валидный JSON, но нарушает правила; `details` перечисляет **все** проблемы сразу |
| 500 `internal_error` | непредвиденная ошибка; наружу без стека, в лог — со стеком |

Разделение 400/422 намеренное: 400 — «не смог разобрать», 422 — «разобрал, но данные не подходят».

## Принятые решения и границы

- **PUT vs PATCH.** PUT — полная замена: не прислали `tags` — они станут пустыми.
  PATCH меняет только переданные поля и требует хотя бы одно.
- **Фильтр по нескольким тегам — AND по умолчанию:** «work и home» ожидаемее, чем «work или home»;
  OR доступен через `match=any`.
- **Пустой результат — это 200 с пустым списком**, а не 404.
- **Пустые теги не ошибка.** UI часто шлёт `["work", ""]` из-за лишней запятой; ронять запрос
  из-за этого вреднее, чем тихо почистить. А вот `#hash` — уже осознанный ввод, отвечаем 422.
- **Не сделано осознанно:** аутентификация, персистентность, rate limiting, CORS,
  переименование тега сразу во всех заметках, полнотекстовый индекс (сейчас `q` — линейный
  проход по кандидатам, что нормально до десятков тысяч заметок).

## Тесты

`npm test` (`node --test`) — 40 тестов в двух файлах, каждый поднимает реальный HTTP-сервер
на случайном порту и ходит по нему через `fetch`; моков нет.

- `test/notes.test.js` — CRUD, валидация, коды ошибок, нормализация тегов, операции с тегами;
- `test/list.test.js` — фильтры, AND/OR, поиск, сортировка, пагинация, `/tags` со счётчиками.

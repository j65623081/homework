# Notes API — заметки с тегами

Мини-сервис заметок с тегами на Laravel. Хранилище — один JSON-файл на диске,
без базы данных. Пять эндпоинтов, у каждого запроса заранее описанный в `SPEC.md`
ожидаемый ответ, с которым сверяется факт.

Домашнее задание после занятия 1, направление **Backend** (Задание 1: «Мини-API
с проверяемым поведением»). Тема — «сервис заметок с тегами» из списка вариантов задания.

---

## Запуск

Нужен **PHP 8.2** и **Composer**. Проверено на PHP 8.2.29 и Composer 2.9.2, Laravel 12.66.0.
Базы данных, Docker и сети не требуется.

```bash
cd api && composer install
```

```bash
cp api/.env.example api/.env && cd api && php artisan key:generate
```

```bash
cd api && php artisan serve --port=8000
```

Сервис поднимется на `http://localhost:8000`, базовый путь — `/api`.

### Тесты

```bash
cd api && php artisan test
```

Ожидаемый результат — **66 passed (393 assertions)**. Тесты не ходят в сеть и не читают
и не пишут рабочий `api/storage/app/notes.json`: каждый работает со своим файлом
во временном каталоге, а `ApiTestCase` сверяет контрольную сумму рабочего файла
до и после каждого теста и падает, если он изменился.

### Стиль

```bash
cd api && ./vendor/bin/pint --test
```

### Важно про `.env`

На машине, где проект писался, **не установлен `pdo_sqlite`**. Laravel 12 по умолчанию
держит сессии и кэш в БД, поэтому в `.env.example` зафиксированы `SESSION_DRIVER=file`,
`CACHE_STORE=file`, `QUEUE_CONNECTION=sync`. Возврат этих значений к умолчаниям уронит
приложение на первом же запросе.

## Что умеет

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/notes` | Список с фильтрами `tag`, `q` и пагинацией `limit`, `offset` |
| `POST` | `/api/notes` | Создание |
| `GET` | `/api/notes/{id}` | Одна заметка |
| `PUT` | `/api/notes/{id}` | Обновление, идемпотентное |
| `DELETE` | `/api/notes/{id}` | Удаление |

Полный контракт — схемы тел, коды ответов, поведение на границах — в [`SPEC.md`](SPEC.md).
Он источник истины; расхождение между ним и кодом считается дефектом кода.

### Проверить руками

```bash
curl -X POST http://localhost:8000/api/notes -H "Content-Type: application/json" -d "{\"title\":\"Buy bread\",\"tags\":[\"Work\",\" work \",\"home\"]}"
```

Вернёт `201` и теги `["work","home"]` — нормализованные: `trim`, нижний регистр, дубли схлопнуты.

```bash
curl "http://localhost:8000/api/notes?limit=-1"
```

Вернёт `422` с указанием поля `limit`.

> На Windows тело с кириллицей передавайте через stdin
> (`printf '...' | curl --data-binary @-`): UTF-8 в аргументе `-d` портится
> при передаче в `curl.exe`, и сервис честно отвечает `400 malformed_json`.

## Принятые решения

Восемь спорных мест закрыты человеком на этапе спецификации, до написания кода.
Каждое с обоснованием — в разделе «Открытые вопросы» `SPEC.md`.

| Вопрос | Решение |
|---|---|
| `?tag=` без совпадений | `200` с пустым списком: у тегов нет закрытого перечня значений |
| Регистр, дубли, пробелы в тегах | Чиним молча: `trim`, нижний регистр, дедупликация |
| Пустой тег в массиве | `422` — это ошибка клиента, а не мусор, который надо подчистить |
| Неизвестные поля в теле | `422 unknown_fields` — ловит опечатку `titel` сразу |
| Повторный `PUT` тем же телом | `200`, идемпотентно; `updated_at` не сдвигается |
| `PUT` по несуществующему `id` | `404`, upsert не выполняется |
| Границы `limit` / `offset` | Невалидное — `422`, а не тихий clamp |
| Испорченный файл-хранилище | `500`, файл **не** перезаписывается |

## Что не сделано и что упрощено

Раздел не для галочки: границы объёма записаны так же тщательно, как то, что внутри.
Полный список — «Чего точно не делаем» в `SPEC.md`.

**Не реализовано сознательно:**

- аутентификация, авторизация, пользователи — сервис однопользовательский;
- полнотекстовый поиск: `q` — подстрочное совпадение, без морфологии и ранжирования;
- сортировка по выбору клиента: порядок фиксирован спецификацией;
- мягкое удаление, история версий, вложения, реестр тегов как отдельная сущность;
- пагинация курсором, `ETag`, условные запросы.

**Упрощено, и это может выстрелить:**

- **Конкурентная запись не поддерживается.** Блокировок файла нет. Два одновременных
  `POST` потеряют одну заметку. Для локального однопользовательского стенда приемлемо,
  для реального использования — нет.
- **Отдельного `405` нет.** Неверный метод и несуществующий маршрут одинаково дают
  `404`. Решение осознанное, но независимый аудит назвал его спорным с точки зрения
  HTTP-семантики.
- **У `offset` нет верхней границы.** `?offset=999999999999999999999` вернёт `200`,
  приведя значение к максимуму типа `int`, а не `422`. Найдено аудитом, признано
  допустимым и зафиксировано в `SPEC.md`, а не исправлено.
- **Живая проверка не автоматизирована.** Тесты гоняют только PHPUnit; сценарий
  с `curl` выполнялся руками и в CI не повторяется.

**Что осталось непроверенным — честно:**

- **Не все решения прошли независимый взгляд.** Из четырёх решений, принятых агентом
  без вопроса человеку на шаге 5 (приоритет `unknown_fields`, ответ на тело-не-объект,
  ответ на пустое тело, порядок проверок), аудит целенаправленно рассмотрел одно.
  Три остались вне его бюджета.
- **Спецификацию никто не оспорил по существу.** За пять сессий человек согласился
  со всеми рекомендациями агента. Решения защитимые, но отсутствие отвергнутых
  вариантов — это риск, а не признак качества. Аудит шага 7 закрыть его не мог:
  он не имел доступа к журналу и оценивал `SPEC.md` как готовый документ.

## Сравнение двух прогонов

Наивный прогон лежит в [`naive/`](naive/) нетронутым, с промптом дословно —
[`naive/NAIVE.md`](naive/NAIVE.md).

**Условия.** Наивный прогон — одна фраза «сделай API для заметок с тегами»
в изолированной сессии без спецификации, без правил проекта и без упоминания стека.
Итоговый прогон — та же тема, но по `SPEC.md` и `AGENTS.md`, написанным до кода.

**Что выбрал агент, оставшись один.** Node.js 22 с нулём зависимостей — при том,
что `AGENTS.md` фиксирует PHP и Laravel. Девять эндпоинтов вместо пяти: сверх контракта
появились `GET /health`, `GET /tags` со счётчиками, `PATCH`, `POST /notes/:id/tags`
и `DELETE /notes/:id/tags/:tag`. Поля в ответе — `createdAt` в camelCase, тогда как
спека фиксирует `created_at`. И главное: **хранилище в памяти** — данные не переживают
перезапуск процесса. По условиям задания это прямое нарушение, но задания субагент
не видел. Это и есть цена наивного промпта: не плохой код, а хороший код, отвечающий
не на ту задачу. Тот факт, что расхождение стека и хранилища оказалось таким полным,
заодно доказал, что изоляция сессии сработала — правила проекта в неё не просочились.

**Где решения разошлись по существу, а не по объёму.** Наивный прогон схлопывает
пробел внутри тега в дефис: `"to do"` становится `to-do`. Пустой тег он **молча
выбрасывает** — клиент не узнаёт, что часть данных исчезла. Итоговый прогон на том же
входе отвечает `422` с указанием индекса `tags.1`: пустой тег — ошибка клиента, а не
мусор, который сервис должен подчистить за него. Ни один из двух вариантов не является
единственно верным; разница в том, что во втором случае выбор сделал человек и записал
причину, а в первом — модель, молча.

**Всего в `naive/NAIVE.md` перечислено 22 решения**, принятых агентом за человека:
от длины `title` и предела размера тела до разрешённых символов в теге и нормализации
Unicode. В итоговом прогоне каждое из них либо принято человеком на этапе интервью,
либо явно записано в допущения `SPEC.md`.

**Где наивный прогон оказался лучше — это тоже честно.** Он справился быстрее:
рабочий сервис с 40 тестами за один промпт против пяти сессий. Часть его решений
совпала с тем, что человек выбрал независимо: отвергать неизвестные поля, отдавать
`200` на пустую выборку, разделять `400` и `422` по принципу «не разобрал / разобрал,
но не годится». Он предусмотрел коды `405`, `413` и `415`, которых в итоговом контракте
нет. И его тесты сразу поднимали реальный HTTP-сервер, без моков.

**Вывод не в том, что второй прогон «лучше».** Он в том, что в первом невозможно
отличить продуманное решение от случайного: и удачные догадки, и хранилище в памяти
выглядят в коде одинаково уверенно. Сверить их не с чем, потому что контракта нет.
Во втором прогоне у каждого решения есть строка в `SPEC.md`, и именно поэтому
независимый аудит смог проверить сервис за один проход и сказать, что расхождений нет.

### Три эпизода, которые стоит прочитать в журнале

- **Откат в начале сессии 1.** Агент, составив план, сразу побежал его выполнять
  и начал строить обвязку до спецификации. Всё откачено `git reset --hard`,
  план переписан по перечню условий задания.
- **Проверка поймала не агента, а меня** (сессия 1, наивный прогон). Субагент
  отчитался «40 тестов пройдено», ручной прогон дал `MODULE_NOT_FOUND` и ноль из одного.
  Неверной оказалась команда проверки, а не отчёт. Вывод команды доказывает, что
  команда выполнилась, а не что она была правильной.
- **Находка оказалась хуже, чем её нашли** (сессия 3). Тест, написанный до правки,
  показал, что `POST` на испорченное хранилище не просто отвечал успехом, а **дописывал
  заметку в испорченный файл**. Ручным `curl` этого не увидели, потому что проверяли
  только `GET`.

### Запреты, которые сработали

Правила в `AGENTS.md` подпёрты механизмом — `.claude/settings.json` со списком `deny`.
Проверено в сессии 2: `php artisan migrate` и `docker ps` отклонены программой.
Незапланированный случай — составная команда с `grep` по `.env` отклонена **целиком**,
запрет ловит не только прямое чтение секретов, но и попытку заглянуть в файл внутри
конвейера.

Отдельно: `composer create-project` запускался с флагом `--no-scripts` не для скорости —
post-install скрипты Laravel выполняют `php artisan migrate --graceful`, то есть штатная
установка сама нарушила бы запрет на миграции, тихо, внутри `composer`.

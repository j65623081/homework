## Как запустить и проверить

```bash
cd api && php artisan test                 # 60 passed
cd api && php artisan serve --port=8000    # стенд
cd api && ./vendor/bin/pint --test         # стиль
```

Тело запроса с кириллицей через curl передавать **только через stdin**
(`printf '...' | curl --data-binary @-`). UTF-8 в аргументе `-d` на Windows
портится при передаче в `curl.exe`, и сервис честно отвечает `400 malformed_json` —
это ошибка проверки, а не кода. Подробности — в `sessions/session-2.md`.

## Известные проблемы

1. ~~**Порядок проверок при испорченном хранилище.**~~ **Закрыто в сессии 3.**
   Порядок оставлен как есть (тело валидируется до чтения файла), переформулирован
   сценарий 10 `SPEC.md`, который ему противоречил. Обоснование записано в спеке:
   клиент должен узнавать о своей опечатке независимо от состояния диска на сервере.
2. **Четыре решения приняты агентом без вопроса человеку** (приоритет
   `unknown_fields`, тело-не-объект → `400`, пустое тело → `422`, порядок проверок).
   Перечислены в `sessions/session-2.md`, раздел «Что решено молча». В аудит.
3. **Человек согласился с 13 рекомендациями агента из 13** за две сессии.
   Отсутствие отвергнутых вариантов — риск оценки. В аудит отдельным вопросом.
4. **Конкурентная запись не поддерживается.** Блокировок файла нет сознательно
   (записано в «Чего точно не делаем»), но два одновременных `POST` теряют заметку.
5. **Живая проверка не автоматизирована.** Тесты гоняют только PHPUnit; сценарий
   с curl выполнен руками и в CI не повторяется.

6. **Самопроверка сессии 3 не является независимым взглядом.** Три находки нашёл
   тот же агент, который писал спецификацию в сессии 1 и знает, что в ней написано.
   Её слепые зоны совпадают со слепыми зонами спеки. Аудит шага 7 это не заменяет.

7. **Локальные коммиты не запушены.** На `origin/main` один коммит, локально — больше.

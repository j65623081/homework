# План выполнения ДЗ №2

## Контекст

**Зачем это делается.** ДЗ №1 сдано на 93/100 (оценка преподавателя 9/10, медиана потока 89).
Задание №2 — про другое: не «дать агенту контекст и правила», а что происходит, когда рядом
появляется **недоверенный текст, живой проект и больше одного агента**. Три пункта обязательны:
работающий результат, субагенты в работе, workflow. Остальное — в плюс к баллу.

**Что берём.** Фича в существующем Notes API (`j65623081/homework`, тот же репозиторий):
`POST /api/notes/import` — загрузка пачки заметок из внешнего файла с ключом идемпотентности,
плюс веб-UI над ним, плюс автоматизированный живой прогон. Выбор не случайный:

- импортируемый файл — это буквально **недоверенный текст**, то есть полигон для инъекций
  возникает сам собой, а не выдумывается отдельно;
- **идемпотентность** — по прямому указанию задания то место, где агент чаще всего пишет
  правдоподобный, но неверный код;
- автоматизация живого прогона закрывает **известную проблему №5** из `sessions/STATE.md`
  («живая проверка не автоматизирована, curl выполнен руками»).

**Формат.** Соло. Роли команды имитируются отдельными сессиями и ветками. Это **не команда**
в смысле задания, и в `README.md` так и будет написано прямым текстом — командный плюс
к оценке на этом не заявляется.

5. **Спека — источник истины.** `AGENTS.md` обязывает: новый эндпоинт, поле или код ошибки —

6. **Инъекции — только в помеченных фикстурах.** В `README.md` сказать, что это учебные закладки,

- **Доказать тремя попытками:** прямая команда, обход через `node -e`/`python -c`, обход через
  третью утилиту. Вывод отказа — целиком, не пересказом.

Файлы: `.claude/hooks/`, `.claude/settings.json`.
**Коммит:** `Шаг 2: PreToolUse-хук вместо текстового запрета, три попытки обхода отклонены`

### Шаг 3. Workflow — обязательный пункт задания (сессия 6)

### Шаг 4. Инструменты и замеры (сессия 6)

Закрывает главную претензию преподавателя. По каждому — **протокол из материалов**: сначала
«что это, ничего не устанавливай», потом отдельным запросом «проверь с точки зрения
безопасности, дай вердикт», и только потом установка.

- `gh` CLI — в ДЗ №1 его не было («Отсутствуют: `gh` CLI»);
- индекс кодовой базы — GitNexus или Graphify. **Замер:** один и тот же вопрос к коду
  («где разбирается тело запроса и кто это вызывает») до индексации и после — время, токены,
  качество ответа;
- оптимизатор контекста — `context-mode` или `rtk`. **Честная цифра**, не заявленная
  (в эфире: заявляют 99 %, реально 20–30 %);
- Playwright — для ветки фронта, агент сам прогоняет сценарии в браузере;
- голосовой ввод — попробовать хотя бы раз, строчка в отчёте.

Каждый — запись в `sessions/TOOLS.md` по формату (тип, установка, зачем, проверка).
**Тупик — тоже запись:** поставили, не подошло, сняли.

Файлы: `sessions/TOOLS.md`.
**Коммит:** `Шаг 4: инструменты, проверка до установки, замер до и после`

### Шаг 5. Три worktree, три роли параллельно (сессия 6 → 7)

Обязательный пункт 2 и плюсовой пункт про worktrees закрываются одним шагом.

```bash
git worktree add ../hw2-backend -b feature/import
git worktree add ../hw2-ui      -b feature/ui
git worktree add ../hw2-checks  -b feature/checks
git worktree list
```

| Ветка | Роль | Зона ответственности |
|---|---|---|
| `feature/import` | бекендер | `POST /api/notes/import` по SPEC v2 + PHPUnit-тесты на сценарии приёмки. Тесты **не трогают** рабочий `api/storage/app/notes.json` — правило проекта |
| `feature/ui` | фронтендер + дизайнер | `api/public/ui/` — статическая страница на vanilla JS: список, фильтр по тегу, поиск, форма импорта. Экранирование HTML — то самое место, где всплывёт инъекция из импортированного файла |
| `feature/checks` | QA | скрипт живого прогона по критериям приёмки `SPEC.md` (curl + проверка кодов и полей). Закрывает известную проблему №5. Фикстуры: отсутствующий файл-хранилище, испорченный файл, `?limit=-1` |

Правила прогона:

- каждому агенту — своя папка, **запрет трогать чужую**;
- **мержу я, агент не мержит** (формулировка из материалов);
- **пока три агента не закрылись — новых требований не отправляем.** Это прямая работа
  над зоной роста №4;
- **замер:** та же работа параллельно и последовательно → таблица «время / контекст главной
  сессии / качество». Не удивляемся, если параллельно медленнее — выигрыш в контексте;
- конфликты при merge и их разбор — в журнал;
- **уборка обязательна:** `git worktree remove …` + `git worktree prune`, показать
  `git worktree list` до и после.

**Коммиты:** по одному в каждой ветке + merge-коммиты в `main`.

### Шаг 6. Агент-ломатель (сессия 8, отдельное окно)

Отдельная сессия, **не тот агент, что писал код**: автор не бывает независимым проверяющим.
Промпт из материалов, минимум 10 итераций по смерженному результату: кривые и пустые данные,
границы, повторные отправки, одновременные запросы, неверный порядок вызовов, очень длинные
строки, чужие идентификаторы. Отдельно — гонки на импорте и повтор ключа идемпотентности.

Итог: список найденного по опасности → либо правка кода, либо честная запись в «известные
проблемы». Если сломать не удалось — так и написать, перечислив, что именно проверено.

**Коммит:** `Шаг 6: прогон агентом-ломателем, найденное и что с ним сделано`

### Шаг 7. Изоляция и недоверенный текст (сессия 9, роль «безопасник»)

### Шаг 8. Независимый аудит в отдельном окне (сессия 10)

**Не субагентом** — это прямая зона роста из разбора: субагент делит бюджет с родительской
сессией и в ДЗ №1 упёрся в `session limit`, не дойдя до живого стенда. Отдельное окно Claude Code
(или облачная сессия) даёт ту же изоляцию без ресурсного потолка.

Аудитор **без доступа к `sessions/`** сверяет `SPEC.md` v2 с фактическим поведением: коды,
имена полей, формат ошибки, идемпотентность на повторах. Расхождение — повод спросить человека,
а не тихо поправить контракт под код.

**Коммит:** `Шаг 8: независимый аудит в отдельном окне`

## Как проверяем, что всё работает

```bash
cd api && php artisan test              # весь вывод, включая падения
cd api && php artisan serve --port=8000 # стенд
cd api && ./vendor/bin/pint --test      # стиль
```

Дальше — вручную и скриптом QA-ветки:

1. корректный импорт → показать код и тело ответа;
2. **повтор с тем же ключом идемпотентности** → тот же ответ, дублей в хранилище нет;
3. повтор с тем же ключом и другим телом → код из спеки;
4. заведомо ошибочный запрос → формат ошибки совпадает со `SPEC.md`;
5. три пограничных случая: нет файла-хранилища, испорченный файл, `?limit=-1`;
6. UI открывается на `http://localhost:8000/ui/`, импортированная заметка со спрятанной
   инструкцией отображается **как текст**, а не выполняется;
7. `git worktree list` и `git log --oneline --graph` — видно три ветки и слияния;
8. `git status` — лишнего не тронуто, `homework.pdf`, `materials/`, `naive/` нетронуты.

Фраза «всё работает» без вывода команды ответом не считается — это правило проекта
и одновременно зона роста из разбора.

## Чего в этом плане осознанно нет

- **Команды из живых людей** — соло; командный плюс не заявляем.
- **Базы данных, Docker в самом сервисе, новых зависимостей в `composer.json`** — прямой запрет
  условий задания №1, он остаётся в силе.
- **ADB/WDA** — нет мобильного приложения и устройства под задачу.
- **Полнотекстового поиска, авторизации, конкурентной записи** — за границей `SPEC.md`,
  раздел «Чего точно не делаем» остаётся границей объёма, а не пожеланием.
